---
title: "تطبيقات OAuth"
description: "أتِح للآخرين ربط حساباتهم في نُشر بمنتجك."
---

يتصرف مفتاح API باسم منظمتك *أنت*. أما **تطبيق OAuth** فهو للاتجاه المعاكس:
يمنحه مستخدمو منتجك حق الوصول إلى حساباتهم *هم* في نُشر.

## سير العمل

1. أنشئ تطبيق OAuth من *Settings → Developers* (الإعدادات ← المطوِّرون).
2. وجِّه المستخدم إلى عنوان URL الخاص بالتفويض؛ ليوافق من جانب نُشر.
3. يتلقى تطبيقك رمز وصول يبدأ بالبادئة `pos_`.
4. أرسله في الترويسة `Authorization` — كما هو، دون `Bearer` — تمامًا مثل
   مفتاح API. ويستدل الخادم منه على المنظمة المانحة.

```bash
curl https://platform.nushir.com/api/public/v1/integrations \
  -H "Authorization: pos_xxxxxxxxxxxx"
```

## النطاق

يمتلك رمز الوصول `pos_` في المنظمة المانحة النطاق نفسه الذي يمتلكه مفتاح API
في منظمتك: السطح بأكمله. لا تطلب من المستخدمين الوصول إلا عندما يحتاج منتجك
إليه فعلًا، وتوقَّع إلغاءه في أي لحظة.

## الإلغاء

يلغي المستخدمون المنح من إعدادات المطوِّرين الخاصة بهم؛ وتفشل رموز الوصول
الملغاة فورًا مع `401`. تعامَل مع ذلك كحالة طبيعية لا كخطأ — واطلب من المستخدم
إعادة الربط.
