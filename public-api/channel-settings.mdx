---
title: "Channel settings"
description: "The per-platform object that POST /posts requires."
---

Each entry in `posts` can carry a `settings` object. What belongs in it depends
on the channel's `identifier`, and for several platforms it is **required** —
omit it and the call returns `400`.

<Note>
Drafts may save incomplete `settings` so you can build a post incrementally.
The saved choices still need validation before scheduling or approval. A saved
draft is not confirmation that its settings are ready to publish.
</Note>

## Where the shape comes from

Each platform's settings are defined by its provider in the application, so this
list follows what the server will actually accept. When a platform changes its
API, the accepted fields change with it.

## Common platforms

<AccordionGroup>
  <Accordion title="tiktok">
    An incomplete draft can start with:

    ```json
    { "__type": "tiktok", "title": "Draft for review" }
    ```

    This example is deliberately incomplete. Before approval or scheduling,
    complete the provider settings in Nushir or use the confirmed MCP settings
    flow. Read the current schema with MCP Integration Schema and current creator
    choices with `tiktokGetCreatorInfo`.

    | Field | Selection required for Direct Post |
    | --- | --- |
    | `content_posting_method` | Explicitly choose `DIRECT_POST` for publication or `UPLOAD` for a TikTok inbox draft. |
    | `privacy_level` | Choose a current permitted creator audience; never preset it. Nushir currently restricts Direct Post to Self only while application review is pending. |
    | `comment`, `duet`, `stitch` | Boolean interaction choices, subject to creator permissions and media type. These are not `disable_*` fields. |
    | `autoAddMusic` | `yes` or `no`; automatic music applies to photos. |
    | `brand_organic_toggle`, `brand_content_toggle`, `disclose` | Accurate commercial disclosure choices. Branded content cannot use Self only. |
    | `posting_consent` | `true` only after the user explicitly authorizes this exact post and posting method. Changed choices require fresh consent. |

    `UPLOAD` sends content to TikTok's inbox for the creator to finish publishing.
    It does not apply Direct Post privacy or interaction settings. Never choose
    it automatically to bypass an incomplete Direct Post request. Review photo
    titles and video captions in TikTok where the selected mode requires it.

    The native review panel and MCP `settingsReadiness` identify missing or invalid
    choices before approval. Saving completed settings keeps the post as a draft;
    approval separately validates media and a future publish time.
  </Accordion>

  <Accordion title="reddit">
    ```json
    {
      "__type": "reddit",
      "subreddit": [{ "value": { "name": "r/example", "title": "Post title" } }]
    }
    ```

    A subreddit is required. Each subreddit has its own posting rules, and a
    post accepted by the API can still be removed by that subreddit's
    moderation.
  </Accordion>

  <Accordion title="youtube">
    ```json
    {
      "__type": "youtube",
      "title": "Video title",
      "type": "public",
      "thumbnail": { "id": "med_01H9" }
    }
    ```

    A title is required — YouTube has no concept of an untitled upload.
  </Accordion>

  <Accordion title="instagram">
    ```json
    { "__type": "instagram", "post_type": "post", "collaborators": [] }
    ```

    `post_type` may be `post`, `reel` or `story`. Media is required regardless;
    Instagram accepts no text-only post.
  </Accordion>

  <Accordion title="pinterest">
    ```json
    {
      "__type": "pinterest",
      "board": "BOARD_ID",
      "title": "Pin title",
      "link": "https://example.com"
    }
    ```

    A board is required.
  </Accordion>

  <Accordion title="x, mastodon, bluesky, threads">
    ```json
    { "__type": "x" }
    ```

    No required fields. Multi-part posts become native threads on these
    platforms — see [threads](/general/composer/threads-and-comments).
  </Accordion>
</AccordionGroup>

## Finding the shape for any platform

Two reliable ways, rather than guessing:

1. Configure one post of that type in the composer, then read it back with
   `GET /posts` and copy the `settings` shape.
2. `GET /integration-settings/{id}` returns the channel's stored defaults.
