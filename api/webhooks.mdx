Nushir sends an HTTP POST to your endpoint whenever a publishing event occurs — whether a post goes live successfully, encounters an error, gets approved by a reviewer, or is first created. Webhooks let you react in real time: update your CMS, trigger downstream workflows, send Slack alerts, or log activity to your own data store without polling the API.

## Available Events

| Event | Description |
|---|---|
| `post.published` | A scheduled post was successfully published to a channel. |
| `post.failed` | A post failed to publish after all retry attempts were exhausted. |
| `post.approved` | A reviewer approved a draft post in the approval workflow. |
| `post.created` | A new draft post was created, either via the dashboard, API, or CLI. |

## Registering a Webhook

### Via the Dashboard

<Steps>
  <Step title="Open Webhook Settings">
    Navigate to **Settings → API → Webhooks**, then click **Add Endpoint**.
  </Step>
  <Step title="Enter Your Endpoint URL">
    Provide your publicly accessible HTTPS URL. Nushir will deliver all selected events to this address.
  </Step>
  <Step title="Select Events">
    Choose which events you want this endpoint to receive. You can subscribe to one or all available events.
  </Step>
  <Step title="Copy Your Signing Secret">
    After saving, Nushir displays a one-time signing secret. Copy it immediately and store it securely — you will use it to verify incoming payloads.
  </Step>
  <Step title="Save the Endpoint">
    Click **Save**. Nushir sends a test ping to confirm your endpoint is reachable.
  </Step>
</Steps>

### Via the API

You can also register endpoints programmatically with a `POST` to `/v1/webhooks`:

```bash title="Register a webhook endpoint"
curl -X POST https://api.nushir.com/v1/webhooks \
  -H "Authorization: Bearer <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-app.com/webhooks/nushir",
    "events": ["post.published", "post.failed"]
  }'
```

## Payload Structure

Every event delivery shares the same envelope. Here is an example payload for a `post.published` event:

```json title="post.published payload"
{
  "event": "post.published",
  "timestamp": "2026-09-01T09:00:05Z",
  "data": {
    "post_id": "post_xyz789",
    "channel_id": "ch_abc123",
    "channel_type": "instagram",
    "published_at": "2026-09-01T09:00:05Z",
    "text": "Launching v2.0 today."
  }
}
```

## Verifying Signatures

<Warning>
  Always verify the webhook signature before processing a payload. Skipping this check means your endpoint could act on forged or replayed requests from third parties.
</Warning>

Nushir signs every payload with **HMAC-SHA256** using your endpoint's signing secret. The signature is included in the `X-Nushir-Signature` request header as a hex digest. To verify it, compute the HMAC of the raw request body with your secret and compare it to the header value.

<CodeGroup>
```javascript title="Node.js verification"
const crypto = require("crypto");

function verifyNushirSignature(rawBody, secret, signatureHeader) {
  const expected = crypto
    .createHmac("sha256", secret)
    .update(rawBody, "utf8")
    .digest("hex");

  // Use timingSafeEqual to prevent timing attacks
  const expectedBuf = Buffer.from(expected, "hex");
  const receivedBuf = Buffer.from(signatureHeader, "hex");

  if (expectedBuf.length !== receivedBuf.length) return false;
  return crypto.timingSafeEqual(expectedBuf, receivedBuf);
}

// Express example
app.post("/webhooks/nushir", (req, res) => {
  const signature = req.headers["x-nushir-signature"];
  const rawBody = req.rawBody; // ensure you have the raw buffer

  if (!verifyNushirSignature(rawBody, process.env.NUSHIR_WEBHOOK_SECRET, signature)) {
    return res.status(401).send("Invalid signature");
  }

  const event = req.body;
  // handle event.event === "post.published" etc.
  res.sendStatus(200);
});
```

```python title="Python verification"
import hashlib
import hmac
from flask import Flask, request, abort

app = Flask(__name__)
WEBHOOK_SECRET = os.environ["NUSHIR_WEBHOOK_SECRET"]

def verify_nushir_signature(raw_body: bytes, secret: str, signature_header: str) -> bool:
    expected = hmac.new(
        secret.encode("utf-8"),
        raw_body,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, signature_header)

@app.route("/webhooks/nushir", methods=["POST"])
def nushir_webhook():
    signature = request.headers.get("X-Nushir-Signature", "")
    raw_body = request.get_data()

    if not verify_nushir_signature(raw_body, WEBHOOK_SECRET, signature):
        abort(401, "Invalid signature")

    event = request.get_json()
    # handle event["event"] == "post.published" etc.
    return "", 200
```
</CodeGroup>

## Retry Policy

If your endpoint responds with a non-2xx HTTP status code, or if the request times out (Nushir waits up to **10 seconds** per attempt), the delivery is automatically retried on the following schedule:

| Attempt | Delay after previous failure |
|---|---|
| 1st retry | 1 minute |
| 2nd retry | 5 minutes |
| 3rd retry | 30 minutes |

After three consecutive failures, Nushir marks the event as **failed** and stops retrying. You can view failed deliveries and manually trigger a resend from **Settings → API → Webhooks → Delivery Logs**.

<Tip>
  Return a `200 OK` response as quickly as possible — before doing any heavy processing. Offload the actual work to a background queue so your endpoint never times out and causes unnecessary retries.
</Tip>
