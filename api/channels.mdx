Channels represent the social accounts and publishing destinations you connect to Nushir. The Channels API lets you list every connected channel — including its current status and usage data — and manage custom webhook-based channels without touching the dashboard. You reference channel IDs from this API when creating and filtering posts.

---

## GET /v1/channels

List all channels connected to your Nushir workspace.

### Response fields

<ResponseField name="id" type="string">
  Unique identifier for the channel. Use this value in the `channel_ids` field when creating posts.
</ResponseField>

<ResponseField name="name" type="string">
  Display name of the channel as configured in the dashboard.
</ResponseField>

<ResponseField name="type" type="string">
  Platform type. Common values: `instagram`, `x`, `linkedin`, `facebook`, `tiktok`, `bluesky`, `custom`.
</ResponseField>

<ResponseField name="status" type="string">
  Connection status: `active` (publishing works) or `disconnected` (re-authentication required).
</ResponseField>

<ResponseField name="channel_count_used" type="integer">
  Number of scheduled (non-published) posts currently queued on this channel.
</ResponseField>

### Example

<CodeGroup>
```bash title="Request"
curl https://api.nushir.com/v1/channels \
  -H "Authorization: Bearer nushir_live_xxxx"
```

```json title="Response — 200 OK"
{
  "data": [
    {
      "id": "ch_01abc123",
      "name": "Brand Instagram",
      "type": "instagram",
      "status": "active",
      "channel_count_used": 14
    },
    {
      "id": "ch_02xyz456",
      "name": "Company LinkedIn",
      "type": "linkedin",
      "status": "active",
      "channel_count_used": 3
    },
    {
      "id": "ch_03cust789",
      "name": "Internal CMS Webhook",
      "type": "custom",
      "status": "active",
      "channel_count_used": 0
    }
  ],
  "total": 3
}
```
</CodeGroup>

<Note>
  OAuth-connected channels such as Instagram, X, LinkedIn, and TikTok are authenticated through the dashboard UI — navigate to **Settings → Channels** to add or re-authenticate them. The API cannot initiate OAuth flows for these platforms.
</Note>

## POST /v1/channels

Connect a new custom channel. Custom channels receive post payloads via a webhook URL you control, making it easy to publish to any platform or internal system that Nushir doesn't natively support.

### Request body

<ParamField body="name" type="string" required>
  A human-readable display name for the channel (e.g. `"Internal Blog CMS"`).
</ParamField>

<ParamField body="type" type="string" required>
  Must be `"custom"` for API-created channels.
</ParamField>

<ParamField body="webhook" type="string" required>
  The HTTPS URL that Nushir will send a POST request to when a post is due to publish on this channel.
</ParamField>

<ParamField body="auth_header" type="string">
  Optional. A static value that Nushir will include in the `Authorization` header when calling your webhook, allowing you to verify that requests originate from Nushir.
</ParamField>

### Example

<CodeGroup>
```json title="Request body"
{
  "name": "Internal Blog CMS",
  "type": "custom",
  "webhook": "https://cms.example.com/hooks/nushir-publish",
  "auth_header": "Bearer my-webhook-secret"
}
```

```json title="Response — 201 Created"
{
  "id": "ch_04blog321",
  "name": "Internal Blog CMS",
  "type": "custom",
  "status": "active",
  "webhook": "https://cms.example.com/hooks/nushir-publish",
  "channel_count_used": 0,
  "created_at": "2025-08-20T15:00:00Z"
}
```
</CodeGroup>

## DELETE /v1/channels/{id}

Disconnect a channel from your workspace. The channel ID is immediately removed from all future publishing activity.

```bash title="Request"
curl -X DELETE https://api.nushir.com/v1/channels/ch_04blog321 \
  -H "Authorization: Bearer nushir_live_xxxx"
```

A successful disconnection returns a `204 No Content` response with an empty body.

<Warning>
  Disconnecting a channel moves **all posts currently scheduled on that channel** back to `draft` status. They will not be published until you reconnect a channel and re-approve those posts. Review your publishing queue before disconnecting an active channel.
</Warning>
