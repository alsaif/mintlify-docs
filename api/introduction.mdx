The Nushir API gives you full programmatic access to your publishing workflow — schedule posts across channels, manage channel connections, and retrieve performance analytics without ever opening the dashboard. The API is available on the **Studio**, **Agency**, and **Enterprise** plans and follows standard REST conventions with JSON request and response bodies.

## Base URL

All API requests are made to the following base URL:

```
https://api.nushir.com/v1
```

Every request must include `Content-Type: application/json` and a valid `Authorization` header. See the [Authentication](/api/authentication) page for details.

## Quick Example

The following request schedules a post to a single channel:

```bash title="Schedule a post"
curl -X POST https://api.nushir.com/v1/posts \
  -H "Authorization: Bearer nushir_live_xxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "channel_ids": ["ch_01abc123"],
    "text": "Hello from the Nushir API!",
    "scheduled_at": "2025-09-01T10:00:00Z",
    "status": "approved"
  }'
```

## Rate Limits

The API enforces a limit of **60 requests per minute** per API key. When you exceed this limit, the API returns a `429 Too Many Requests` response. Check the `Retry-After` header in the response for the number of seconds to wait before retrying.

```json title="429 response body"
{
  "error": {
    "code": "rate_limit_exceeded",
    "message": "You have exceeded the 60 requests/minute rate limit.",
    "retry_after": 14
  }
}
```

<Tip>
  Build exponential back-off into your integration. If you consistently hit rate limits, consider batching requests or caching responses on your end.
</Tip>

## Versioning

The current API version is **v1**, reflected in the base URL path (`/v1`). Nushir follows a conservative versioning policy:

| Version | Status | Base URL |
|---------|--------|----------|
| v1 | Current | `https://api.nushir.com/v1` |
| v2 | Future — breaking changes only | `https://api.nushir.com/v2` |

Minor, backwards-compatible additions (new optional fields, new endpoints) are rolled out continuously without a version bump. Breaking changes — such as removing fields or altering response shapes — are published under a new version number with advance notice.

<Note>
  API access is available on the **Studio**, **Agency**, and **Enterprise** plans only. If you are on the Free or Starter plan, upgrade your plan in **Settings → Billing** to generate API keys.
</Note>
